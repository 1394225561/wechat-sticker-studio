# 动态微信表情投稿预检与组包

规则来自 **2026-10-28** 保存的 [微信表情开放平台制作规范](https://sticker.weixin.qq.com/pages/guide#/#/makingSpecifications#specifications_stickers)快照。当前公开页面和登录后的上传表单尚未复核。表单字段、标签选项、可用权限、版权与 AI 声明由作者在投稿时确认；ZIP 供整理与逐项上传使用。

## 清单和命令

从[单品模板](../assets/single-submission.template.json)或[专辑模板](../assets/album-submission.template.json)开始。用 `shasum -a 256 文件路径` 记录每个已确认版本的摘要。清单的 `path` 相对清单位置，`stickers` 的数组顺序就是投稿顺序。图片名称可含中文和空格。

可为每枚表情分别设置 `frame_count` 锁定预期帧数，或通过 `durations_ms` 同时锁定帧数和逐帧时长。两项都填写时，`durations_ms` 的条数必须等于 `frame_count`。两项都省略时，报告记录实际解码帧数。

```sh
"$py" -B "$skill/scripts/pack_submission.py" submission.json
"$py" -B "$skill/scripts/pack_submission.py" submission.json --output submission.zip
```

第一条只预检。两条命令都返回 JSON，失败退出码为 1，报告列出字段或素材序号、路径和原因。同名 ZIP 会报错，改用新输出路径即可。成功的 ZIP 包含编号 GIF、配图、填写说明及路径已改为包内相对路径的清单。

- **单品**填写一个 GIF、含义词和建议选用的标签。后台可选标签及单品审核条件在提交时人工核对。快照排除了推广形象、推广信息与人物肖像。
- **专辑**填写 8–24 个 GIF、各自的含义词、专辑名称、介绍、版权信息和三张配图。开启赞赏时将 `appreciation` 写为含 `enabled: true`、`message`、`guide`、`thanks` 的对象。两张图与其他配图一样用 `path` 和 `sha256` 引用。
- 两类清单都可加 `ai_disclosure` 记录生成合成内容说明，或加 `form_notes` 字符串数组带上提交时需人工核对的字段。

## 本机规则

| 材料 | 格式与尺寸 | 本机大小上限 |
| --- | --- | --- |
| 动态表情图 | GIF，240 × 240，无限循环 | 500,000 字节 |
| 专辑横幅 | JPEG 或 PNG，750 × 400 | 500,000 字节 |
| 专辑封面 | 透明 PNG，240 × 240 | 500,000 字节 |
| 聊天面板图标 | 透明 PNG，50 × 50 | 100,000 字节 |
| 赞赏引导图 | PNG 或 GIF，750 × 560 | 500,000 字节 |
| 赞赏致谢图 | PNG 或 GIF，750 × 750 | 500,000 字节 |

专辑名称、介绍、版权信息和含义词分别限 8、80、10、4 字，赞赏引导语为 5–15 字。本机按 Unicode 字符计数，英文字母、空格和标点各计一个，混排的后台实际计数方式待核。横幅或赞赏图含透明像素、含义词带标点或重复会给出提示。封面和图标要求可解码出透明背景及可见主体。

投稿包也执行本项目的动态 GIF 检查，包括至少两个可解码帧、正时长及每帧实际透明和可见主体。填写了目标帧数或逐帧时长时，预检会与成品的实际解码结果比对。上传表单字段、角色和风格一致性、创作权利及审核判断由作者人工确认。
